**Lesson:** the vulnerable `next` came from reusing `Taller-PatronSaga/frontend` (its `package.json` pins `next@16.3.5`). That project should be upgraded too.

## Practices that make the audit meaningful
- Every Python image installs from a **fully pinned** `requirements.txt` (generated with `pip freeze` in a clean `python:3.12-slim`), so the audited versions are exactly the deployed ones.
- `package-lock.json` is committed and the image builds with `npm ci`. The `.gitignore` deliberately does **not** ignore lockfiles (unlike `PA-Taller1/.gitignore`).
- Base images are pinned by tag (`python:3.12-slim`, `node:22-slim`, `supabase/postgres:15.14.1.170`, `prefecthq/prefect:3.8.6-python3.12`). Every application container runs as a non-root user.
- **Not in scope (Q-15 = pip + npm only):** OS packages inside images (Debian `chromium`, etc.). Adding an image scan (e.g. Trivy) would cover them.

## Reproduce
```bash
docker run --rm -v "$PWD:/repo:ro" python:3.12-slim sh -c 'pip install -q pip-audit==2.9.0 && for f in /repo/services/*/requirements.txt /repo/ingestion/requirements.txt; do pip-audit -r $f; done'
cd frontend && npm audit
```
